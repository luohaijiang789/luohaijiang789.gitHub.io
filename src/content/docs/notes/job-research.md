## 先收集真实岗位

选定一个地区和一类岗位，收集几份仍有效的原始招聘说明。搜索关键词可以从 AI Security Engineer、Product Security Engineer、Detection Engineer 等开始，再以实际职责判断是否匹配。

这只是研究入口，不代表这些岗位在任何地区都有相同要求，也不代表目前有合适空缺。

## 建一张有证据的表

| 字段 | 记录什么 |
| --- | --- |
| 岗位与来源 | 公司原始招聘页、岗位名称、地点、查看日期 |
| 主要职责 | 用自己的话归纳要解决的问题 |
| 必需与优先条件 | 分别记录，不混在一起 |
| 我的证据 | 能对应要求的真实项目、经历或作品 |
| 当前差距 | 是缺知识、缺经验，还是缺表达能力？ |
| 下一步 | 一个可以执行和验收的行动 |
| 工作资格 | 招聘页明确写了什么，哪些仍未知？ |

## 用项目讲清能力

用“问题 → 我的职责 → 行动 → 验证 → 局限”组织介绍。没有实际做过的工作，不写成已经完成的经历。

英文练习模板：

> I built [what] to address [problem]. My contribution was [action]. I verified it by [evidence]. One limitation is [boundary].

## 本轮任务

1. 选择一个感兴趣的岗位类别。
2. 用原始招聘说明整理反复出现的要求。
3. 选一个最值得补足的差距，安排一次可复现的技术实验。
4. 完成项目后，再更新能力证据。

[权限边界实验](/notes/tool-guard/)能提供一次练习；职业能力仍需通过持续的项目、实际协作与深入研究来积累。
