**最终成果：** 一个能够区分允许与拒绝调用的本地权限实验，一张信任边界图，以及一份记录证据和局限的技术复盘。

不设固定完成天数。先做完一轮，再根据实际卡住的地方补基础。

<PathChecklist />

## 第一步：理解请求与权限

阅读[一次 HTTP 请求](/foundations/http/)。画出请求发起者、服务器和资源，解释身份认证与授权的区别。

**验收：** 能说明“登录成功”为什么不代表“可以读取所有文件”。

## 第二步：理解智能体的风险

阅读[工具调用的信任边界](/security/tool-boundaries/)，操作权限演示。比较普通调用和外部文档诱导的调用。

**验收：** 能指出模型建议与执行授权的分界，以及独立检查需要哪些信息。

## 第三步：用证据检验结论

使用[证据与结论模板](/thinking/evidence/)，记录输入、预期、实际结果和尚未验证的问题。

**验收：** 能区分测试观察与安全结论，指出反例和未覆盖的边界。

## 第四步：交付并解释实验

按[项目说明](/projects/tool-guard/)运行规则与测试，写出一个未覆盖的风险，并整理技术复盘。

**验收：** 提供可运行代码、允许与拒绝测试、实际结论、局限和复现步骤。完成了才写进作品集。

## 把这一轮变成下一轮的起点

用[证据与结论模板](/thinking/evidence/)复盘，把仍然讲不清的问题留到下一轮。用[图解检查表](/design/visual-explanation/)修改你的流程图，再从[岗位研究](/global/job-research/)里找一个值得继续补足的能力。
